## 1. Visión General del Proyecto

- **Nombre:** GameVault — Gestor de Colección Personal y Backlog de Videojuegos.
- **Asignatura:** DWEC (Desarrollo Web en Entorno Cliente) — 2º DAWT (Curso 2026/2027).
- **Enunciado Oficial:** Basado en [`ENUNCIADO.md`](./ENUNCIADO.md) (29 requisitos organizados en 3 Sprints evaluables para la entrega final `v1.0`).
- **Tablero de Trello:** [GameVault - Proyecto DOM (DWEC)](https://trello.com/b/b1iXcn0Q/gamevault-proyecto-dom-dwec).
- **Objetivo Principal:** Aplicación web cliente sin servidor backend (Single Device SPA/MPA) que permite a cada usuario registrado gestionar su biblioteca física y digital de videojuegos, registrar horas de juego, estados de progreso y expansiones (DLCs), con almacenamiento seguro local en el navegador del cliente.

## 3. Modelo de Datos y Esquemas JSON

Toda la persistencia se realiza en el almacenamiento web del navegador:

### A. Almacenamiento de Sesión (`sessionStorage`)

1. **Clave `gamevault_sesion`**:
   Guarda el usuario autenticado actualmente y su rol:
   ```json
   {
     "usuario": "pablo_dev",
     "rol": "administrador"
   }
   ```
   - `usuario`: `string` no vacío (recortado con `trim()`).
   - `rol`: estrictamente `'usuario'` o `'administrador'`.

2. **Clave `gamevault_aviso_pendiente`**:
   Permite pasar avisos diferidos entre páginas tras una redirección:
   ```json
   {
     "mensaje": "Te has registrado con éxito. ¡Bienvenido a GameVault!",
     "tipo": "success"
   }
   ```
   - `tipo`: `'success'`, `'danger'`, `'warning'`, o `'info'`.

---

### B. Almacenamiento Local (`localStorage`)

1. **Clave `gamevault_usuarios`**:
   Array con la colección de usuarios registrados:
   ```json
   [
     {
       "nombre": "admin",
       "usuario": "admin",
       "correo": "admin@gamevault.com",
       "clave": "8c6976e5b5410415bde908bd4dee15dfb167a9c873fc4bb8a81f6f2ab448a918",
       "claveHash": "8c6976e5b5410415bde908bd4dee15dfb167a9c873fc4bb8a81f6f2ab448a918",
       "rol": "administrador",
       "creadoEn": "2026-11-10T19:00:00.000Z"
     }
   ]
   ```
   - **Regla del 1er usuario:** Si la lista está vacía, el primer usuario en registrarse es **`administrador`**. Los siguientes son **`usuario`**.
   - **Criptografía:** `clave` y `claveHash` almacenan el resumen SHA-256 en hexadecimal (64 caracteres) generado por `resumirClave(clave)` de `js/clave.js`. Nunca se guarda la contraseña en texto plano.

2. **Clave `gamevault_juegos_<nombreUsuario>`** *(Sprint 2)*:
   Cada usuario tiene su propia clave aislada en `localStorage` (aislamiento multiusuario). Almacena un array con sus videojuegos:
   ```json
   [
     {
       "id": "gv_1731268800000_a1b2",
       "titulo": "Elden Ring",
       "plataforma": "PC",
       "formato": "digital",
       "fechaAdquisicion": "2024-06-21",
       "horasJugadas": 120,
       "estadoProgreso": "completado",
       "sku": "GAME-RPG-0042",
       "codigoBarras": null,
       "ubicacionEstanteria": null,
       "tiendaDigital": "Steam",
       "dlcs": [
         {
           "titulo": "Shadow of the Erdtree",
           "estado": "completado"
         }
       ],
       "creadoEn": "2026-11-10T20:00:00.000Z"
     }
   ]
   ```

## 4. Esquema Técnico de Validaciones y Algoritmos

Todas las validaciones deben implementarse en JavaScript nativo como funciones puras:

| Campo | Regla / Algoritmo | Expresión Regular o Fórmula | Mensaje de Error Oficial |
|---|---|---|---|
| **Nombre de Usuario** | Alfanumérico con guiones, 3-15 caracteres, no repetido | `/^[a-zA-Z0-9_-]{3,15}$/` | «El usuario debe tener entre 3 y 15 caracteres alfanuméricos y no estar ocupado.» |
| **Correo Electrónico** | Formato estándar de email | `/^[^\s@]+@[^\s@]+\.[^\s@]+$/` | «Introduce una dirección de correo electrónico válida.» |
| **Contraseña (Registro)** | Mínimo 8 caracteres, al menos 1 minúscula (`\p{Ll}`), 1 mayúscula (`\p{Lu}`) y 1 dígito numérico (`\d`) | `/\p{Ll}/u`, `/\p{Lu}/u`, `/\d/`, `longitud >= 8` | «La contraseña debe tener al menos 8 caracteres, una minúscula, una mayúscula y un número.» |
| **Repetir Contraseña** | Coincidencia idéntica | `valor === inputClave.value` | «Las contraseñas no coinciden.» |
| **Aceptación Términos** | Casilla marcada obligatoria | `inputCheckbox.checked === true` | «Debes aceptar las condiciones de uso para continuar.» |
| **Título del Juego** | Texto obligatorio (2-100 caracteres) | `titulo.trim().length >= 2 && <= 100` | «El título del videojuego es obligatorio (entre 2 y 100 caracteres).» |
| **Plataforma** | Opciones cerradas | `'PC'`, `'PlayStation 5'`, `'Xbox Series X'`, `'Nintendo Switch'`, `'Retro'` | «Selecciona una plataforma válida de la lista.» |
| **Formato** | Selección excluyente | `'fisico'` o `'digital'` (activa campos condicionales) | «Debes seleccionar el formato del juego (Físico o Digital).» |
| **Fecha Adquisición** | No futura (`max = hoy` dinámico) | `new Date(fecha) <= new Date(hoy)` | «La fecha de adquisición es obligatoria y no puede ser posterior a hoy.» |
| **Horas Jugadas** | Entero >= 0 | `/^\d+$/` y `>= 0` | «Las horas jugadas deben ser un número igual o superior a 0.» |
| **Estado Progreso** | Opciones cerradas | `'pendiente'`, `'jugando'`, `'completado'`, `'abandonado'` | «Selecciona el estado de progreso actual del juego.» |
| **Código SKU** | Patrón obligatorio de catálogo | `/^GAME-[A-Z]{3}-\d{4}$/` *(ej: GAME-RPG-0042)* | «El código de catálogo debe seguir el formato GAME-XXX-0000 (ej. GAME-RPG-0042).» |
| **EAN-13 (Condicional)** | 13 dígitos numéricos y algoritmo de control ponderado módulo 10 | `/^\d{13}$/` + Algoritmo EAN-13 (ver detalle abajo) | «El código de barras debe tener 13 dígitos y un dígito de control EAN-13 válido.» |
| **Estantería (Condicional)** | Formato balda | `/^EST-[A-Z]-\d{2}$/` *(ej: EST-A-03)* | «La ubicación debe indicar estantería y balda en formato EST-X-00 (ej. EST-A-03).» |
| **Tienda Digital (Condicional)** | Opciones cerradas | `'Steam'`, `'PlayStation Store'`, `'Nintendo eShop'`, `'Epic Games Store'`, `'Xbox Store'` | «Selecciona la tienda digital donde adquiriste el juego.» |
| **Grupo DLCs (Dinámico)** | 0 a 3 elementos clonados de `<template id="tpl-dlc">` | Cada fila requiere Título (string) y Estado (`pendiente`, `jugando`, `completado`) | «Cada DLC añadido debe incluir un título válido y su estado.» |

### Algoritmo Oficial de Control EAN-13:
```javascript
export function validarEAN13(codigo) {
  if (typeof codigo !== 'string' || !/^\d{13}$/.test(codigo)) return false;
  const digitos = codigo.split('').map(Number);
  const digitoControl = digitos.pop();
  
  // Suma ponderada: posiciones impares (peso 1), posiciones pares (peso 3) indexando desde 0
  const suma = digitos.reduce((acc, d, idx) => acc + d * (idx % 2 === 0 ? 1 : 3), 0);
  const calculado = (10 - (suma % 10)) % 10;
  return calculado === digitoControl;
}
```

## 5. Arquitectura de Páginas y Mapa de Selectores DOM

### 1. `index.html` (Pública — Inicio de sesión)
- **Ruta de acceso:** Cualquier usuario. Si hay sesión activa (`haySesion()`), redirige de inmediato a `listado.html`.
- **Selectores e IDs esenciales:**
  - Formulario: `<form id="form-login" novalidate>`
  - Inputs: `<input id="login-usuario">`, `<input id="login-clave">`
  - Botón: `<button id="btn-login" type="submit">`
  - Caja de avisos: `<div id="region-avisos" role="status" aria-live="polite">`
  - Enlace a registro: `<a href="registro.html">`
- **Flujo:**
  - Evitar doble envío (`disabled = true` en el botón mientras se ejecuta `resumirClave`).
  - Si la autenticación falla, lanza aviso de error (`lanzarAviso`), limpia el campo `#login-clave` y le devuelve el foco (`focus()`).

---

### 2. `registro.html` (Pública — Alta de usuarios)
- **Ruta de acceso:** Cualquier usuario. Si ya hay sesión, redirige a `listado.html`.
- **Selectores e IDs esenciales:**
  - Formulario: `<form id="form-registro" novalidate>`
  - Inputs:
    - `#registro-usuario` (con caja de error `#error-usuario`)
    - `#registro-correo` (con caja de error `#error-correo`)
    - `#registro-clave` (con caja de error `#error-clave`)
    - `#registro-repetir-clave` (con caja de error `#error-repetir-clave`)
    - `#registro-terminos` (checkbox con `#error-terminos`)
  - Indicador reactivo de contraseña: `#requisitos-clave`
    - `#req-longitud`: marca si tiene >= 8 caracteres.
    - `#req-minuscula`: marca si cumple `/\p{Ll}/u`.
    - `#req-mayuscula`: marca si cumple `/\p{Lu}/u`.
    - `#req-digito`: marca si contiene `/\d/`.
  - Botón: `<button id="btn-registro" type="submit">`
- **Flujo:**
  - Mientras el usuario teclea en `#registro-clave` (evento `input`), las clases `.requisito-cumplido` se activan en tiempo real en la lista de requisitos.
  - Al completar el registro con éxito:
    1. Se registra el usuario en `localStorage` con `registrarUsuario`.
    2. Se inicia sesión automáticamente en `sessionStorage` con `iniciarSesion`.
    3. Se guarda un aviso diferido con `guardarAviso('Te has registrado con éxito. ¡Bienvenido a GameVault!', 'success')`.
    4. Redirección a `listado.html`.

---

### 3. `listado.html` (Privada — Catálogo y backlog)
- **Ruta de acceso:** Cualquier usuario con sesión activa (`haySesion()`). Si no hay sesión, `location.replace('index.html')`.
- **Selectores e IDs esenciales:**
  - Cabecera común: `<header id="cabecera-app">` (iniciada con `iniciarCabecera()`).
  - Buscador: `<input id="campo-buscador" type="search">`, `<button id="btn-limpiar-busqueda">`.
  - Contador: `<span id="contador-resultados">`.
  - Mensaje vacío: `<div id="mensaje-vacio" hidden>`.
  - Contenedor de tarjetas: `<div id="contenedor-juegos">`.
  - Plantilla de videojuego: `<template id="tpl-juego">` (tarjeta horizontal con carátula a la izquierda, badges de plataforma/estado, horas y botones de edición y borrado).
  - Modal accesible de confirmación: `<dialog id="modal-borrar">`
    - `#nombre-juego-borrar`: Nombre del juego a eliminar.
    - `#btn-confirmar-borrado`: Confirma borrado.
    - `#btn-cancelar-borrado`: Cierra el modal con `modal.close()`.
  - Paginación: `<nav id="paginacion">`
    - Botones `#btn-pag-anterior`, `#btn-pag-siguiente`, contenedor `#numeros-pagina`.
- **Flujo:**
  - Carga los juegos de la clave `gamevault_juegos_<usuario>`.
  - Buscador con *debounce* (300ms) que normaliza tildes y mayúsculas (`normalize('NFD')`).
  - Al pulsar "Borrar", se abre el diálogo nativo con `dialog.showModal()`, sin librerías externas.
  - Al borrar un juego, se elimina del almacenamiento, se refresca la vista y se dispara `lanzarAviso('Videojuego eliminado', 'info')`.

---

### 4. `ficha.html` (Privada — Alta y Edición)
- **Ruta de acceso:** Requiere sesión (`haySesion()`). Si no, `location.replace('index.html')`.
- **Modos de funcionamiento:**
  - Alta: URL limpia `ficha.html`.
  - Edición: URL con parámetro `ficha.html?id=ID_DEL_JUEGO`. Si el ID no existe en los juegos del usuario, redirige a `listado.html` con aviso de error diferido.
- **Selectores e IDs esenciales:**
  - Formulario: `<form id="form-juego" novalidate>`
  - Inputs base: `#juego-id` (hidden), `#juego-titulo`, `#juego-plataforma`, `#juego-sku`, `#juego-fecha`, `#juego-horas`, `#juego-estado`.
  - Radios de formato: `<input type="radio" id="formato-fisico" name="formato" value="fisico">` y `<input type="radio" id="formato-digital" name="formato" value="digital">`.
  - Sección Físico: `<fieldset id="seccion-fisico">` con `#juego-ean` y `#juego-estanteria`.
  - Sección Digital: `<fieldset id="seccion-digital">` con `#juego-tienda`.
  - Grupo dinámico DLCs: `<div id="seccion-dlcs">`
    - Botón: `<button id="btn-anadir-dlc" type="button">` (se desactiva al alcanzar 3 DLCs).
    - Contenedor: `<div id="contenedor-dlcs">`.
    - Plantilla: `<template id="tpl-dlc">` (incluye inputs únicos con `htmlFor`, botón de eliminar fila).
  - Botones principales: `<button id="btn-guardar-juego" type="submit">`, `<a id="btn-cancelar-juego" href="listado.html">`.
- **Flujo Condicional:**
  - Al conmutar `#formato-fisico`, se muestra `#seccion-fisico` (`hidden = false`, inputs `disabled = false`) y se oculta `#seccion-digital` (`hidden = true`, inputs `disabled = true`). Viceversa al conmutar `#formato-digital`.
- **Rejilla de Metadatos (Alineación validada):**
  - Fila 2 de formulario:
    - SKU: `col-md-3 text-nowrap`
    - Fecha: `col-md-3 text-nowrap`
    - Horas: `col-md-2 text-nowrap`
    - Estado de progreso: `col-md-4 text-nowrap` (mantiene el label en una sola línea y alineado con Plataforma).

---

### 5. `usuarios.html` (Privada Administradores — Gestión)
- **Ruta de acceso:** Requiere sesión (`haySesion()`) Y rol administrador (`esAdministrador()`). Si entra un usuario común, se guarda un aviso diferido de advertencia y se redirige con `location.replace('listado.html')`.
- **Selectores e IDs esenciales:**
  - Cabecera común: `<header id="cabecera-app">`
  - Buscador: `<input id="buscador-usuarios">`
  - Tabla: `<table id="tabla-usuarios">`, cuerpo `<tbody id="cuerpo-tabla-usuarios">`.
  - Filas dinámicas: Nombre, Correo, Insignia de Rol actual y Botón de alternancia de rol (`data-usuario="nombre"`).
  - **Seguridad obligatoria:** El botón de la fila del administrador que tiene la sesión iniciada debe estar **deshabilitado (`disabled`)** con un atributo `title="No puedes retirar tu propio rol de administrador"` para impedir la auto-revocación y asegurar que siempre exista al menos un administrador en el sistema.

## 6. Módulos JavaScript y API Interna

### 1. `js/clave.js`
- `resumirClave(clave: string): Promise<string>`
  Calcula el hash SHA-256 en hexadecimal (64 caracteres) usando `crypto.subtle.digest`.

### 2. `js/sesion.js`
- `obtenerSesion(almacen): Sesion | null`
- `iniciarSesion(usuario, rol, almacen): Sesion`
- `guardarSesion(usuario, rol, almacen)` (alias de `iniciarSesion`)
- `cerrarSesion(almacen): void`
- `haySesion(almacen): boolean`
- `esAdministrador(almacen): boolean`
- `esAdmin(almacen)` (alias de `esAdministrador`)
*Resiliencia:* Si el JSON en `sessionStorage` es inválido o no cumple el esquema, devuelve `null` sin lanzar excepción.

### 3. `js/usuarios.js`
- `obtenerUsuarios(almacen): Usuario[]`
- `guardarUsuarios(usuarios, almacen): void`
- `obtenerUsuarioPorNombre(nombre, almacen): Usuario | null`
- `existeUsuario(nombre, almacen): boolean`
- `registrarUsuario(datos, almacen): Promise<Usuario>` (1er usuario -> `administrador`, resto -> `usuario`)
- `autenticarUsuario(nombre, clavePlana, almacen): Promise<Usuario | null>`
- `cambiarRolUsuario(nombre, nuevoRol, almacen): Usuario | null`
- `eliminarUsuario(nombre, almacen): boolean`
- `vaciarUsuarios(almacen): void`

### 4. `js/avisos.js`
- `lanzarAviso(elemento, mensaje, tipo): CustomEvent`
  Emite `CustomEvent('aviso', { bubbles: true, cancelable: true, detail: { mensaje, tipo } })`.
- `normalizarTipoAviso(tipo): 'success' | 'danger' | 'warning' | 'info'`
- `renderizarAviso(region, mensaje, tipo, opciones): HTMLElement`
  Genera la alerta DOM nativa con clases Bootstrap (`alert alert-<tipo> alert-dismissible fade show`), texto seguro (`textContent`), botón de cierre y `setTimeout(5000)`.
- `guardarAviso(mensaje, tipo, almacen): void`
- `consumirAviso(almacen): { mensaje, tipo } | null`
- `iniciarAvisos(documento, opciones): void`
  Registra el oyente único en `document` para capturar cualquier aviso emitido y renderiza avisos diferidos de `sessionStorage`.

### 5. `js/cabecera.js`
- `iniciarCabecera(documento, opciones): void`
  Sincroniza `#sesion-usuario`, `#sesion-rol`, muestra/oculta `#nav-admin` según `esAdministrador()` y asocia el evento `click` en `#btn-logout` a `cerrarSesion()` y redirección.

### 6. `js/registro.js`
- `iniciarRegistro(documento, opciones): void`
  Controlador de `registro.html`. Guarda de sesión, indicador interactivo de requisitos de clave, validaciones en `blur`, prevención anti-doble clic y redirección con aviso diferido.

### 7. `js/login.js`
- `iniciarLogin(documento, opciones): void`
  Controlador de `index.html`. Guarda de sesión, validación de credenciales con SHA-256 (`autenticarUsuario`), vaciado y foco automático en contraseña ante error, y prevención anti-doble envío.

### 8. `js/rutas.js`
- `protegerPaginaPrivada(opciones): boolean`
  Guarda de páginas privadas estándar (`listado.html`, `ficha.html`). Redirige a `index.html` con `location.replace` si no hay sesión.
- `protegerPaginaAdmin(opciones): boolean`
  Guarda de páginas exclusivas de administrador (`usuarios.html`). Redirige a `index.html` sin sesión, o a `listado.html` con aviso de error si el usuario no es administrador.

### 9. `js/juegos.js`
- `obtenerClaveJuegos(usuario: string): string`

## 7. Sistema de Eventos, Propagación y Accesibilidad

1. **Validación en tiempo real de formularios:**
   - Fase de captura (`useCapture = true`): oyente `blur` registrado en el formulario `<form>` para validar cada campo individual al abandonarlo sin necesidad de poner oyentes en cada `<input>`.
   - Fase de burbuja: una vez que el campo ha sido visitado (`dirty`), se escucha el evento `input` o `change` para actualización reactiva instantánea del estado de error.
2. **Atributos de accesibilidad en validación:**
   - Campo erróneo: `input.setAttribute('aria-invalid', 'true')` y `input.setAttribute('aria-describedby', 'id-caja-error')`.
   - Caja de error: `<div id="id-caja-error" class="invalid-feedback d-block" role="alert">`.
3. **Delegación de eventos:**
   - En `listado.html`: Un solo oyente `click` en `#contenedor-juegos` detecta si el clic provino de un botón `.btn-borrar` o `.btn-editar` mediante `e.target.closest('button')`.
   - En `usuarios.html`: Oyente delegado en la tabla para botones de alternancia de rol.
4. **Región de Avisos:**
   - `<div id="region-avisos" role="status" aria-live="polite">` presente en las 5 páginas.

## 10. Estándares de Calidad y Formato (ESLint y Prettier)

### A. ESLint (`eslint.config.js`)
Configuración plana moderna de ESLint con 4 reglas estrictas adicionales:
- `'no-var': 'error'`: Prohíbe terminantemente `var`, forzando el uso de `let` y `const` para prevenir problemas de hoisting y ámbito de función.
- `'prefer-const': 'error'`: Exige `const` en todas las variables que no sean reasignadas, garantizando inmutabilidad referencial y código más predecible.
- `'eqeqeq': 'error'`: Obliga a la igualdad estricta (`===` y `!==`), eliminando errores sutiles derivados de la coerción implícita de tipos.
- `'no-duplicate-imports': 'error'`: Prohíbe múltiples sentencias `import` hacia un mismo módulo en un archivo, manteniendo dependencias limpias.

### B. Prettier (`.prettierrc`)
- Formateo estándar homogéneo para JavaScript, HTML, CSS, JSON y Markdown.
- `"endOfLine": "auto"`: Evita discrepancias de saltos de línea (CRLF en Windows vs LF en Linux/CI) al comprobar el formato con `prettier --check .`.

### C. Comandos de Verificación
- `npm run lint`: Ejecuta `eslint .` (0 errores, 0 advertencias).
- `npm run format:check`: Ejecuta `prettier --check .` (todos los archivos limpios).
- `npm run format`: Corrige automáticamente el estilo en todo el proyecto.

1. **Lectura obligatoria del contexto:** Al empezar cualquier tarea, lee primero este archivo para mantener la coherencia con el diseño y el contrato de entrega.
2. **Commits progresivos y frecuentes ("poco a poco"):** Realiza commits pequeños, atómicos y frecuentes a medida que desarrolles partes lógicas (ej. 1º código base, 2º pruebas unitarias, 3º integración en páginas/HTML). **NUNCA hagas un solo commit gigante por tarea**. Sigue Conventional Commits (`feat:`, `fix:`, `test:`, `docs:`, `style:`).
3. **Pull Requests con permiso previo explícito:** Pide SIEMPRE autorización al usuario antes de abrir (`gh pr create`), registrar en el README o fusionar (`gh pr merge`) cualquier Pull Request.
4. **Documentación del contexto:** `.contexto-agente.md` y `GEMINI.md` se mantienen en el repositorio por requerimiento docente para trazabilidad. Manténlos siempre actualizados de forma continua.
5. **Inyección de dependencias:** Funciones que usen `localStorage`, `sessionStorage` o navegación deben admitir parámetros por defecto para permitir su sustitución en tests unitarios (`AlmacenFalso`).
6. **Resiliencia ante datos corruptos:** Cada acceso a `JSON.parse` debe protegerse con bloques `try / catch` que devuelvan valores por defecto seguros (`null` o `[]`).
7. **Protección contra XSS:** No inyectar texto introducido por usuarios con `innerHTML`; usar `textContent` o creación segura de nodos DOM.
